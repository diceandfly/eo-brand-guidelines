# 콘텐츠 전수검사 플랜 — 번역 · 장표-내용 충돌 (2026-11-13)

최종 핸드오프 전, 가이드의 **글(국문 · 영문) · 장표(이미지) · 로고 생성기 규칙**이 서로 어긋나는 곳을 빠짐없이 찾는다. 실행은 메인 세션, 서브 세션은 같은 범위를 **독립적으로** 한 번 더 보고 두 결과를 대조한다(교차 검증). 기술부채 플랜(docs/tech-debt-plan.md)과 같은 진행 규칙.

## 0. 원칙
- **찾기와 고치기를 분리.** 각 단계는 발견 목록(아래 형식)만 만든다. 고치는 건 CC-6 에서 한꺼번에, 사용자 결정에 따라.
- **국문이 최종본.** 국문 문장은 다듬지 않는다. 숫자 · 고유명사 · 오타처럼 명백한 불일치만 "국문 수정 제안"으로 올리고 사용자가 정한다. 영문은 국문에 맞춰 메인이 고친다.
- **장표는 사용자 사전 컨펌 규칙.** 장표 쪽이 틀린 경우는 "장표 재수출 필요" 목록으로만 올린다(직접 수정 · 재생성 금지).
- **판단 기준은 문서로 고정.** 용어는 docs/terms.md, 표기는 메모리의 국문 스타일(나열 ' · ', 영어 단어+조사 붙여 씀, "심볼" 표기), 수치 정본 우선순위는 아래 4.
- 범위: 국문 · 영문 가이드 12쪽(실제 콘텐츠 9쪽 + Download 링크 · 생성기), 이미지 280장(언어 공용), 캡션 228개, 섹션 104개, 로고 생성기 문구 · 규칙.

## 1. 발견 목록 형식 (`research/content-check/findings.csv`, 단계별로 행 추가)
| 열 | 내용 |
|---|---|
| id | CC-단계-번호 (예 CC2-017) |
| where | 페이지 › 섹션(앵커 id), 파일:줄(ko · en), 이미지 토큰 |
| type | 번역 누락 · 의미 차이 · 수치 불일치 · 용어 · 표기 · 장표-글 충돌 · 장표 내부 오류 · 캡션 짝 · 생성기-가이드 · 내부 모순 |
| ko / en / slide / tool | 각 쪽의 원문 · 값(장표는 보이는 글자 · 수치) |
| severity | A 사실이 틀림(수치 · 규칙) · B 뜻이 다름 · C 표기 · 문체 |
| proposal | 고칠 쪽과 고칠 내용 |
| owner | 메인(영문 · 코드) · 사용자(국문 · 장표 결정) |
| found_by | main · sub · both (교차 검증 결과) |

## 2. 단계

### CC-0 인벤토리 (자동, 메인)
- 스크립트 `research/content-check/inventory.mjs`(loadGuide 사용): 페이지 › 섹션 › (본문 문단 · 불릿 · 캡션 · 이미지 토큰 · 배지 · 참조 링크 · 컬러 칩) 를 국문 · 영문 나란히 JSON/CSV 로.
- 각 조각에서 **수치 토큰 추출**: `H/30` · `(4/30)H` · `0.47H` · `15mm` · `70px` · `1/33` · `140%` · `1.05배` · `−2%` · `#F9EE3A` · `C5 M0 Y95 K0` · 개수(12컬럼 · 6로우 · 7색) · 비율(16:9 · 4:3).
- 산출: `inventory.json`, 페이지별 요약표. 서브 세션 잠금 없음(읽기 전용).

### CC-1 자동 대조 (메인 → 서브 교차)
1. **국문 ↔ 영문 수치 집합**: 섹션 · 캡션 단위로 수치 토큰 multiset 이 같은지. 다르면 행 추가.
2. **구조 짝**: 섹션 · 서브헤드 · 불릿 개수 · 문단 개수 · 캡션 유무 · 배지 종류(do · dont · con) · `{strike}` · 참조 링크 대상 · 컬러 칩 이름이 1:1 인지.
3. **용어 · 표기**: docs/terms.md 대조(영문 용어 대소문자 · 국문 대응어), 팔레트 7색 이름 대소문자, "심벌" 금지, 국문 나열 구분자, 영문 em/en dash · 따옴표 일관.
4. **번호 토큰**: dont-N · In Use 캡션 번호 · `pattern-dont-N` 등 빈자리 · 순서(메모리 규칙: 발견 즉시 양쪽 재번호 대상).
- 서브: 같은 스크립트를 쓰지 않고 독립 방법(직접 grep · 별도 파서)으로 1 · 3 을 다시 뽑아 메인 목록과 대조.

### CC-2 번역 의미 검토 (사람이 읽듯, 페이지 단위로 메인 · 서브 분담 후 교차)
- 국문 문단 ↔ 영문 문단을 나란히 읽고: 누락 · 추가 · 뜻 반전 · 조건/예외 누락(“~일 때만”, “권장/금지”의 강도) · 수량 · 주어 · 지시 대상 차이.
- 분담: 메인 = Logo(Symbol · Signature · Sub Symbol) · Color · Overview · End, 서브 = Typography · Graphic Unit · Graphic Pattern · Applications. 끝나면 **서로 바꿔 한 번 더**(교차) — 두 번 다 본 페이지만 완료.
- 캡션 228개 포함(캡션은 장표와 같이 CC-3 에서 한 번 더 봄).

### CC-3 장표 ↔ 글 대조 (이미지 280장을 실제로 열어 봄)
- 장표마다: (a) 장표에 찍힌 글자 · 수치 · 라벨 ↔ 그 섹션 본문 · 캡션(국문 · 영문) (b) 장표 주제 ↔ 섹션 주제(엉뚱한 장표 · 이전 버전) (c) Do/Don't 배지 ↔ 장표 표시(대각선 · 체크) (d) 캡션 번호 ↔ 장표 순서 (e) 장표 안 영문 캡션의 용어 · 철자가 가이드 용어와 같은지 (f) 같은 장표가 두 곳에 쓰일 때 글이 서로 맞는지.
- 분담은 CC-2 와 같게, 교차는 수치가 찍힌 장표(Geometry · Clearspace · Scalability · Inversion · Descriptor · Reference Scale · Levelling · Linespacing · Letterspacing · Grid · Morphology · Grammar 계열)만 두 번.
- 장표가 많은 페이지(Graphic Pattern 66 · Graphic Unit 56 · Typography 49)는 섹션 단위로 끊어 진행 · 기록.

### CC-4 로고 생성기 ↔ 가이드
- 크기 구간(최적 4–15 · 권장 초과 15–25 · 시그니처 가로 4–10 · 세로 10–15–25), 최소 크기, 클리어스페이스 식(H/2 · 오른쪽 0.42 + 0.0012S · 67mm), 다크 변환(확대 2/30 → 오프셋 H/60 · 간격 −H/30), 시그니처 규격(0.47H · 1.3H · 1.35H · 자간 · H/5 · H/100 · H/200), HEX · CMYK, 컬러 페어링 6종 ↔ 가이드 Symbol/Signature 문장 · 장표.
- 생성기 영문 문구(툴팁 · 경고)의 용어가 가이드 영문과 같은지.
- npm test [5] 가 고정한 값과 가이드 문장 값이 같은지(테스트는 코드끼리만 봄).

### CC-5 가이드 내부 모순
- 같은 규칙이 여러 곳에 나올 때 값이 같은지: 예) Symbol › Scalability 의 최적 · 권장 최대 ↔ Signature 의 10mm · 15mm ↔ 생성기, 클리어스페이스 H/2 의 여러 언급, Inversion 규칙의 Symbol · Signature · Typography 상호 참조, Line Unit · 마진 1/22–1/25 등.
- 참조 링크 `[[…]]` 의 라벨이 가리키는 내용과 실제 대상 섹션이 맞는지(자동 라벨은 이름만 맞음).

### CC-6 정리 · 수정 라운드
- findings.csv 를 severity · owner 로 정렬해 사용자에게 한 장 보고: (1) 메인이 바로 고칠 것(영문 · 코드) (2) 국문 수정 제안 — 사용자 결정 (3) 장표 재수출 목록 — 사용자 결정.
- 결정 뒤: 영문 수정 → npm test → 커밋(단계 번호 [CC-6] 머리), 국문은 승인된 것만, 장표는 사용자가 폴더에 넣으면 import.
- 서브 크로스체크: 수정 커밋마다 해당 행이 해소됐는지 · 새 불일치가 생기지 않았는지.

### CC-7 최종 회귀
- npm test · npm run build · preview 로 고친 페이지 렌더 확인(참조 링크 · 칩 · 캡션), EN/KO 패리티 리포트 12/12 유지.

## 3. 교차 검증 방식 (서브 세션)
- 서브는 **메인의 발견 목록을 보기 전에** 자기 담당 범위를 먼저 끝내고 자기 목록을 낸다(앵커링 방지). 그다음 메인 목록과 합쳐 found_by 를 채운다.
- 한쪽만 찾은 항목은 다른 쪽이 재확인해 "맞음 / 오탐" 을 적는다.
- 서브는 파일을 고치지 않는다. 결과는 메인 세션으로 바로 보낸다.

## 4. 수치 정본 우선순위 (충돌 시 어느 쪽을 맞출지 제안할 때)
1. 사용자가 이 세션들에서 확정한 결정(메모리 · 커밋 메시지 · docs/logo-generator/SPEC.md 의 날짜 박힌 결정)
2. 로고 생성기 RULES · GEOM(npm test [5] 고정) — 단 가이드 문장과 다르면 어느 쪽이 맞는지 사용자 확인
3. 국문 가이드 본문
4. 장표(사람이 손으로 만든 것이라 이전 버전이 남아 있을 수 있음)
5. 영문 가이드

## 5. 하지 않음
- 국문 문장 다듬기 · 문체 통일(국문 최종본 원칙). 어색한 문장은 C 등급 "검토 요청"으로만.
- 장표 디자인 평가(정렬 · 색 감각). 글과 충돌하는 사실만.
- 아카이브(public/archive/handoff) — 핸드오프 날 생성물.

## 6. 산출물

## 7. 순서와 대략 규모
CC-0(자동) → CC-1(자동 + 교차) → CC-2(9쪽, 분담 + 교차) → CC-3(280장, 분담 + 수치 장표 교차) → CC-4 → CC-5 → CC-6(사용자 결정) → CC-7.
가장 큰 건 CC-3 — 장표를 실제로 열어 읽어야 해서 페이지 단위로 끊어 진행 상황을 기록한다.
